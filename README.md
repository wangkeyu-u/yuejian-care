# 月间 · 伴侣照护与周期分析

面向伴侣共同使用的中文开源经期照护手记。记录实际经期和感受，把有出处的知识综合成当日建议；可选择用自己的 OpenAI API Key 进一步整理分析。

[在线使用](https://yuejian-personal-journal.soundteal2049.chatgpt.site/) · [GitHub 仓库](https://github.com/wangkeyu-u/yuejian-care)

## 开始使用

1. 在当事人同意的情况下，填写伴侣设置、实际经期开始日和已确认的结束日。结束日不知道可留待确认。
2. 查看今日照护，按当天疼痛、精力、睡眠、出血情况和本人需求调整。月历也可选择其他日期。
3. 首页把知识合成“先减轻负担、吃饭与饮水、休息与相处”三项安排。百科顶部显示同一份方案，文章会标出具体用途；选中的文化仪式也可进入方案。
4. 日期有变化时点“修改本次经期”，保存后会重算月历、周期位置、建议和下次参考日期。
5. 需要 AI 时，点“填写 API Key 并分析”，核对发送预览、确认同意，再主动发起请求。默认建议不需要 Key。

网站不从生日、MBTI、生肖或五行推断一个人的症状、情绪或喜好；支持偏好应由本人表达，任何安排都可跳过或修改。

## 日期修改与同步

- 每次经期使用稳定 ID，分别记录开始日、结束日和状态：`unknown`（结束日未确认）、`ongoing`（尚未结束）、`ended`（已确认结束）。不猜测实际结束日。
- 修改开始日会重算周期位置与下一次参考日期。修改结束日只改变实际出血区间，不重置下一次参考开始日。
- 保存后回到今天，明确显示更新结果。感受小记保持原公历日期，不随经期日期整体平移。
- 同一浏览器、同一网址的其他标签页通过 `storage` 事件更新。旧编辑窗口会拒绝覆盖更新后的经期记录。
- 保存失败时保持已保存记录不变。真实日期与预计日期分开，预计日期不会自动写成一条实际经期。

这里的同步是同一浏览器内的联动，不包含跨设备或跨网址的自动同步。旧站换到新版网址，需要在旧站导出，再在新版“数据管理”导入。

## 下次经期参考

- 少于 3 次实际开始记录时，按手动参考周期估算，默认 28 天。
- 至少 3 次开始记录时，取最近最多 6 个完整间隔的中位数；异常间隔会明确说明并退回手动参考，不悄悄删除记录。
- 同时显示样本数、计算方法和参考窗口。窗口是工程余量，不代表置信区间或已验证准确率。
- 到期未记录新开始日时保留原参考日期；最近经期仍进行中且已到下次参考日时暂停新一轮预测。
- AI 解释这些计算和记录，不生成另一套日期，不改写原始数据。

具体公式见 [预测方法](docs/FORECAST-METHOD.md)。这个工具不能检测排卵、怀孕、安全期或诊断周期变化原因。

## 综合建议与知识来源

内置 48 篇资料：22 篇经期知识、8 篇中医常识和 18 篇文化问答。全部映射到可追溯的本地规则，按周期状态和当日记录合并为有限的行动建议，每项可展开查看触发原因和原文。

- 疼痛、异常出血等提示优先；低精力、睡眠和本人支持偏好影响休息与陪伴安排。
- 中医内容涵盖传统术语、就诊沟通、针灸证据、艾灸风险和中药安全，不自动辨证、开方或提供自行操作教程。
- 文化栏目可关闭，只提供历法背景和可跳过的生活灵感，不参与健康判断或周期计算。
- 未来日期只提供参考安排，不把尚未发生的症状当作事实。

资料逐篇核对日期为 2026-10-26。`paragraphSources` 对应正文段落，`verification.sourceNotes` 说明引用范围。传统理论、医学资料和编辑建议分别标明；出处可追溯不代表疗效已确证。来源日后也可能更新或失效。

## 自带 API Key

仅支持 OpenAI Responses API，默认模型 `gpt-4.1-mini`，可改为自己有权限、支持 Responses 与结构化输出的模型 ID。

- 必须由用户点击分析并确认数据预览。不会自动请求或后台重试。
- Key 经同源 `/api/analyze` 转发到固定的 OpenAI 接口；应用不把 Key 写入源码、浏览器存储、数据库、备份或日志。输入框在提交、关闭时清空。
- 只发送最近最多 24 次经期起止与状态、参考设置、所选日期和结构化感受选项。昵称、生日、城市、喜恶自由文本和文字小记不会发送；服务端补充对应公开知识。
- 请求使用 `store:false`，不等于服务商零保留。费用由 Key 所属 API 账号承担；ChatGPT 登录账号与 API Key 分开管理。
- 服务端重算日期，限制结果结构和可引用文章 ID；拒绝不完整输出、拒答和未知来源。模型仍可能写错，关键结论应核对原文。
- AI 结果只在当前页面暂存；修改相关记录会使旧分析失效。规则生成的医疗优先提示持续保留。

接口与数据边界见 [AI 接入说明](docs/AI-INTEGRATION.md)。API Key 应只填在自己信任的网站或自部署实例，不能提交到 GitHub、Issue 或聊天中。

## 本机数据与迁移

记录默认保存在当前浏览器的 `localStorage`。无需账户，不自动上传、跨设备同步或通知；主动 AI 请求是明确选择的数据发送操作。共享设备的同一浏览器使用者可能看到本地记录。

“数据管理”支持 JSON 导出、导入和清空。导入前显示数量与替换范围，保留一份导入前本机备份供恢复；百科收藏仍保留本机现有选择。更换网址、浏览器或设备时用备份迁移，清理浏览器前先导出。

v2 格式示例：

```json
{
  "version": 2,
  "periods": [{"id": "example-period", "start": "2026-01-01", "end": null, "status": "unknown"}],
  "cycleLength": 28,
  "periodLength": 5
}
```

旧 `starts` 数组迁移为稳定 ID、`end:null`、`unknown`，不补造结束日。v2 存在 `periods` 字段时，即使为空也以它为准。首次写入前备份旧版数据；读取失败不覆盖原始记录，可导出保留。日志按原日期保存。

## 本地运行与部署

使用 Node.js 22.12 或更新版本（本次测试环境为 Node.js 26）：

```sh
npm ci --ignore-scripts
npm start
```

打开 `http://127.0.0.1:4174`。开发服务器同时提供页面和 AI 转发；修改源码后重启服务器。

```sh
npm test
npm run build
npm run validate
```

- `public/`：原生 HTML、CSS、JavaScript、知识与本地规则。
- `worker/`：Web 标准 `Request` / `Response` 服务与 AI 转发，无数据库。
- `scripts/`：本地服务器、单文件 Worker 构建与产物校验。
- `dist/server/index.js`：生成的单文件 ESM Worker，内嵌页面资源，导出 `default.fetch`，适用于 Cloudflare Workers 兼容运行时。

构建不需要本项目的 Site ID 或 API Key。自部署者自行配置托管服务；Sites 部署由其注册工具创建本机 `.openai/hosting.json`，不要复用别人的站点身份。单独静态托管 `public/` 可用本地记录功能，AI 按钮还需要同源 `/api/analyze` 服务。

测试覆盖日期运算、记录验证与迁移、建议规则、预测统计、AI 请求/输出过滤以及完整页面脚本的 DOM 交互。集成测试使用 jsdom 和模拟网络，不代表真实浏览器、实体设备或真实付费 AI 调用验收；本次尚未使用用户的真实 Key 调用 OpenAI。2026-10-28 已补做桌面与手机宽度的真实浏览器交互复验，使用虚构日期与选项。

请用虚构数据报告问题，不在公开 Issue、截图或测试中上传真实经期、生日、API Key 或感受记录。身体或心理不适持续、严重时，应寻求专业帮助。
