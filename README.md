# 月间 · 伴侣照护手记

`yuejian-care` 是一个面向伴侣共同记录的中文静态照护工具。它把经期日期、当日感受和可选的照护安排放在同一份本地手记里，帮助双方根据当下的真实表达协作，而不是替任何人解释身体或情绪。

[在线使用](https://yuejian-personal-journal.soundteal2049.chatgpt.site/) · [GitHub 仓库](https://github.com/wangkeyu-u/yuejian-care)

## 开始使用

1. 打开网站，在“伴侣设置”填写昵称、她表达过的支持偏好，以及不喜欢的安排。
2. 在她同意的情况下，记录最近一次经期的实际开始日；结束日可之后补记。
3. 查看“今日照护”，也可在月历选择前后的日期；根据当天实际感受调整安排。

- 记录应得到当事人的同意，随时可以撤回。
- 伴侣可以一起查看和记录，但不能替对方确认症状、偏好或“应该怎样”。任何活动、陪伴和提醒都应以当事人当下的选择为准。
- 网站不会根据生日、MBTI、生肖、五行或其他标签预测一个人的情绪、经期反应或喜欢的事。
- 数据默认只在当前浏览器保存；没有账户、后台照护者、远程查看或自动通知功能。

## 能做什么

### 记录真实周期

- 记录实际经期开始日和结束日，支持 `unknown`（只确认开始日）、`ongoing`（正在进行）和 `ended`（已确认结束）三种状态。
- 开始日和结束日都可以编辑。编辑开始日会重新对齐周期日和下一次参考开始日；编辑结束日只改变实际经期覆盖范围，不会重置周期预测。
- 真实记录与预计日期分开显示。预计日期不会自动变成新的真实经期。

### 参考安排与照护

- 预测只使用真实开始日加上可调的参考周期长度；默认周期为 28 天，出血持续时间是独立的参考值。
- 首页把知识综合为当天的行动建议：先处理的不适、饮食与日常调护、陪伴和先避开的安排。建议会随实际周期、疼痛、精力、睡眠、出血情况和本人偏好调整。
- 可选填写今天想了解的照护主题，如中药药膳、针灸、艾灸、运动或用品；主题代表兴趣，不代表已确诊或已经接受治疗。
- 每项建议可展开查看触发原因及对应的知识原文。严重疼痛或异常出血相关提示优先展示，文化灵感不改变健康判断。
- 感受小记按用户填写的公历日期保存，不会因为修改周期或开始日而整体平移；历史记录仍对应原来的那一天。
- 可记录心情、疼痛、精力、睡眠、出血情况、照护主题、陪伴需求和文字小记，也可以删除或导出。

### 知识与可选文化栏目

- 内置 48 条可搜索内容：22 条经期知识、8 条中医常识和 18 条传统文化问答，支持分类、收藏和逐条来源链接。
- 经期知识覆盖经前、经期中、结束后、睡眠、用品卫生、异常情况和何时寻求专业帮助等主题。
- 中医常识独立于文化栏目，涵盖传统痛经术语、四诊与就诊沟通、针灸证据、艾灸风险和中药安全；不自动辨证、开方或生成自行治疗步骤。
- 每篇显示资料性质、来源核对日期、逐段原文链接与引用范围。传统理论、医学资料和编辑建议分别注明；科普出处不等于疗效确证。
- 干支、生肖、五行等栏目默认可关闭，只作为文化背景和生活灵感，不参与周期计算或健康判断；开启后可以在综合建议中附带可跳过的生活灵感。

## 综合建议怎样生成

全部 48 篇知识均有可追溯的规则映射，规则池按当天记录选择相关内容，合并成有限的行动建议。不会将 48 篇全文堆进每一天，也不会仅把文章标题列为建议。

- 经前、实际经期、结束后和日期不确定分别处理，预计状态会写明。
- 疼痛和出血情况影响优先顺序；低精力、睡眠困扰和紧绷影响休息与活动安排。
- 中医知识用于饮食沟通、就诊准备、疗法证据与用药安全，不据此自动辨证、处方或生成自行操作教程。
- 未来日期使用参考安排，不能把尚未发生的症状当成事实。
- 综合建议由浏览器内的确定性规则整理，不调用远端模型或上传个人记录。

具体触发和知识映射见 [综合建议规则](docs/ADVICE-RULES.md)。新增字段缺省为空，已有感受记录继续按原公历日期保存。

## 数据格式与迁移

公开版使用 v2 周期记录结构。每条记录包含稳定的 `id`、`start`、`end` 和 `status`：

```json
{
  "version": 2,
  "periods": [
    {
      "id": "period-2026-01-01",
      "start": "2026-01-01",
      "end": null,
      "status": "ongoing"
    }
  ],
  "cycleLength": 28,
  "periodLength": 5
}
```

约定如下：

- `end` 为 `null` 时只能是 `unknown` 或 `ongoing`；`ended` 必须有明确结束日。
- 不会根据参考持续时间猜测实际结束日。
- 如果 v2 数据中存在 `periods` 字段，即使它是空数组，也以它为准，不再回退到旧的 `starts` 字段。
- 首次保存迁移后的数据前，旧版 JSON 会备份在本浏览器的独立键中。导出包含这份备份，清空记录时一并删除。读取失败时不会覆盖原始数据。
- v1 的 `starts` 数组迁移为稳定的 `legacy-YYYY-MM-DD` 记录，状态为 `unknown`、结束日为 `null`。迁移不会凭空补写结束日。
- 日志、偏好和收藏仍按日期或自身记录保存，不因迁移或周期预测而改写历史日期。

## 隐私与使用边界

- 数据使用浏览器 `localStorage` 保存，不上传到本项目服务器，也不跨设备同步。
- 可以在“数据管理”中导出 JSON 备份，或清空当前浏览器中的记录。目前不支持导入，导出文件供自行保存和查看。清除浏览器数据、更换浏览器或使用隐私模式可能导致未导出的记录丢失。
- 在共享设备上使用时，同一浏览器的其他使用者可能看到本地记录；请先确认设备和浏览器的使用边界。
- `dist/` 是可直接部署的静态文件，不需要后台、数据库或构建服务。静态托管平台的访问控制由部署者自行负责。
- 参考周期不是排卵检测、避孕方法、怀孕检测或诊断工具。网站不能替代妇科、全科、心理健康或急诊专业支持；遇到严重或持续的身体/心理不适，应联系当地专业服务。

## 本地运行

需要 Node.js、npm 和 Python 3：

```sh
npm ci --ignore-scripts
npm start
```

然后打开 `http://127.0.0.1:4173`。`npm start` 会用 Python 的静态服务器直接提供 `dist/`；不需要打包步骤。

运行测试：

```sh
npm test
```

项目采用原生 HTML、CSS、JavaScript，不依赖前端框架。`dist/` 可以直接交给静态托管服务；日期运算、数据迁移、伴侣照护和百科筛选有独立的 Node 测试。

欢迎通过 GitHub Issues 报告问题或提交 Pull Request。复现问题时请使用虚构日期和昵称，不要在公开 Issue、截图或测试里上传真实的经期、生日或感受记录。
