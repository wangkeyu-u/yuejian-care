# DeepSeek 小额真实调用核查

日期：2026-10-29；修复版本：4.5.2。

## 范围与费用

使用用户授权的Key，向`https://api.deepseek.com/responses`发起3次生成调用。实际返回模型为`deepseek-flash`，关闭思考模式，返回的思考token均为0。另有一次模型列表查询，不生成回答。

测试适配层只替换网站分析器的上游地址、模型、思考开关和输出上限，复用业务提示词、知识选择与响应校验。**线上网站仍只提供OpenAI连接，本轮没有把DeepSeek Key写入网站设置，也没有给生产服务配置该Key。**分析器内部的`gpt-4.1-mini`仅是通过原有模型格式校验的测试占位值，实际模型以上游返回字段为准。

全部输入都是虚构案例和公开知识，不含当事人的生日、聊天记录或真实健康档案。Key经隐藏标准输入进入测试进程内存，不写入代码、文件、报告或备份；测试进程已经结束。

第三次还产生3条来源不符的记忆候选：它们把偏好内容冒充当前问题的原句。现有逐字来源校验丢弃了这3条，只保留有原句支持的当天短期健康候选。候选并未写入个人档案，也不会自动确认。

## 已落实的修复

- 生成结构改为按culture/tcm/western/psychology命名的四个对象，各自只能选择允许领域的引用ID；服务端转换为原有四分区数组，界面和旧记录格式保持兼容。
- 睡眠、PMS等跨领域资料保留西医与心理两种用途，与百科分类对齐；分期指南仍不被当作心理学专用来源。
- 菜单引用在生成结构中限于nutrition-资料，文化关闭时引用数组须为空。运行时领域检查继续保留。
- 结构化行动拒绝把未回复视作同意；旧记录仍可查看。提示词明确沉默不构成新增安排的授权。
- 已明确记录当前疼痛时，拦截“今天没有她报告的具体不适”等直接矛盾；提示词区分“缺乏某领域解释依据”和“没有不适”。
- 提示词要求brief每领域一条行动，避免重复记录与盘问；核对面条、汤底、酱料、替换食材等配料限制。紧急情境先联系医疗，记录不作为前提。
- 第二次原始结果在修复后离线回放已被拒绝；新增交叉分类、分区来源约束、静默同意与症状否认回归案例。

## 能证明什么

这轮证明真实模型能生成具体步骤，也会在结构正确时给出不合适或互相矛盾的内容。引用与来源护栏确实拦下过错误，不能据此把剩余文本视为已经验证的医学建议。

183项自动测试通过。仅有3次真实生成，包含一次修复后的完整分析、一次最终规则下的急性不适追问；**最终语义修复后的完整分析没有再次付费复测**。没有覆盖四阶段、多模型、不同真实个体，也没有完成临床或长期使用验证。针对已观察表达的文本护栏不是完整的事实或同意语义检测器。

费用控制到此停止，不为凑通过率追加调用。接口格式依据：[DeepSeek Responses API](https://api-docs.deepseek.com/api/create-response/)、[兼容说明](https://api-docs.deepseek.com/guides/responses_api/)、[OpenAI结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)。
