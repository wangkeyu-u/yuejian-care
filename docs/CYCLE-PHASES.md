# 四阶段、聊天线索与显示边界 · 4.4

## 用户能做什么

日历显示月经期、经后卵泡期、排卵参考日、黄体期。上方显示今天的阶段、参考起止与含今天的剩余天数；各段或任意日期可点开同一个日期框，继续查看玄学文化、中医、西医、心理学、饮食与 AI 对话。

医学上，卵泡期从月经开始延续至排卵，与月经期重叠。这里将经后部分单列，是查看日期的界面选择，不是四个互不重叠的生理实体。排卵参考日只是定位锚点，不表示排卵持续一天。

## 本地估算

`public/phases.js` 独立于实际经期计算 `core.js`；不改写实际出血状态或原始日期。

- 已记录的出血范围优先，结束日未知不伪造实际结束；尚未结束的出血不会自动变成黄体期。
- 以现有历史间隔中位数/手动周期估计下一次开始，回看时可使用已知的下一次实际开始日。
- 在21—35天的可用参考间隔内，以“下次开始日减14天”为默认展示锚点。14天是产品简化选择，不是个人实测。页面同时给出按10—16天回推的边界参考，不是个人概率区间。实际周期仍可能无排卵，模型不能据此确认。
- 月经段按实际结束日或出血参考天数；经后至锚点前为经后卵泡段；锚点之后至下一次参考月经前为黄体参考段。参考天数不应被解释成必定持续。
- 核对后的 LH 阳性报告可将报告次日暂作为展示锚点，这是待核对的工程规则；若与本轮日历边界不一致，则显示阶段待确认，不强行拟合。LH不证明已排卵。
- 单次体温、分泌物、症状和行为不自动移动阶段。使用激素避孕、妊娠、哺乳或其他特殊情况时通用估算可能不适用，设置支持暂停；实际出血仍显示。
- 无起点、参考日已到但未记新月经、间隔不适合简化分期、仍在出血且查看未来，或日期越界时保留未知。不把推迟自动滚动为今天的新阶段。

## 聊天导入与行为

日历“从聊天整理线索”支持粘贴最多20段、每段1000字；相对日期以所填参考日解释。先去除姓名、联系方式及无关内容，取得当事人同意后主动调用 API。未调用时文本仅在当前输入框，关闭即清空，不保存整份聊天。

`POST /api/day` 新增 `mode: signals`，仅把确认发送的片段交给模型；不把其他长期记忆、完整个人档案或旧AI回答混入此整理任务。严格结构要求原句、来源ID、发生日、类型和简述。服务端与浏览器核对逐字引文、日期、秘密字符串；开始/结束/LH类别还有肯定表述检查。这些检查不能证明模型理解了真实对话，所有结果仍须人工逐条核对，默认不勾选。

保存明确月经开始/结束报告时，经人工确认更新实际经期，同时保存原句线索；缺少对应开始日、范围冲突或存储已改变时整批不写入。日期、简述均可核对修改。一般行为只影响照护上下文，不作为排卵或黄体期证据。候选处理使用模拟上游验证，未验证真实付费模型的提取准确度。

## 人工标注、保存与清理

日期框可给所选日期起最多32个公历日标注阶段或“暂不确定”，要求填写原因。标注显示为人工判断，不能伪装成检测结果；实际出血优先，新实际周期会截断旧周期标注的应用。选择自动估算可移除标注。单条线索可在同一框发起删除，先预览关联原文、同日条目、记忆版本、派生对话及本机备份，再确认清理，相关参考即时更新；已人工确认的实际经期是独立记录，需到设置修改或移除，不会随删除一句聊天而悄悄消失。

线索与标注位于主资料 `entries[date].signals/phaseHint`，采用原有CAS、本机导入导出和记忆清理流程。已停止使用的来源不再用于阶段推算或AI上下文。新请求记录阶段依赖日期，删除关联来源时会处理派生会话。所有设置、起止、线索或标注改变后刷新日历，旧AI分析按签名失效，不挪动原公历日期。
