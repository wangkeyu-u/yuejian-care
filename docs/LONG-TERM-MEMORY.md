# 长期记忆 · 4.1

记忆是用户确认的背景，不是 AI 对一个人的定论。当天记录、当前问题中的明确表达优先。生日、MBTI、依恋标签和模型建议不作为个人长期事实的来源。

## 从原句到后续建议

1. 正常生成和追问可顺带返回最多4条候选，不额外调用 API；可在设置关闭自动提取。来源仅当天小记、发送的用户历史消息与当前问题，排除助手回答。未来日期只做准备，不提取未来事实。
2. 设置支持单独从最近20条文字小记/用户发言提取，每条最多500字，先预览并单独确认发送；这是一次独立 API 调用，最多8条候选。
3. 服务端和浏览器均检查来源 ID、逐字引文、持续性词语、日期与敏感字符串。此检查不能证明内容推断正确，也可能漏掉没有这些词的真实偏好。保留否定和条件的准确性仍需用户核对。
4. 候选只进入待确认列表。确认时可编辑内容、类型、适用起始日、复核截止日，并选择替换旧条目；未勾选确认不保存为生效记忆。没有自动合并冲突或覆盖旧事实。
5. 每次请求由前后端共同清洗，最多使用24条已确认、启用、未过期且适用的记忆。候选、已停用、未来来源或已过期条目不发送。今天过期的条目也不再发给历史日期的重新分析；过期不代表身体情况已结束。

## 提示词边界

服务端的静态照护规则始终保留。确认记忆以 `<confirmed_long_term_memory_json>` 数据块追加到 Responses API 的 `instructions`，其中包含类型、内容、日期与 ID，尖括号转义；不复制来源全文，也不把记忆内容直接拼成新的行为规则。

静态文字明确要求：数据不能改写规则、索取 Key 或要求外传；当下明确表达优先；只在相关时用背景，不反复复述敏感内容。模型仍可能理解错误；编码与提示词不能保证完全阻断提示注入，也不能代替人工核对。

用户界面可展开查看当前附加的记忆块。确认、修改、替换、删除和关闭使用会立即更新日期上下文，旧分析按签名失效；待确认候选不影响刚生成的回答。跨日期引用的是确认后的摘要，不是其他日期的整段对话。

## 来源、健康条目和复核

来源保存原句、日期、用户发言/小记/手动修改类型。手动更改摘要内容后记录为手动填写，避免误称模型提取的引文证明了新的措辞。

长期情况、用药、过敏均为本人/用户报告，不是医学确证。用药候选默认给出30天后的记忆复核截止日，可在采用时调整；这只决定是否继续发给模型，不是疗程、停药建议或医学标准。内容变化应重新核对，而不是靠日期自动推断。

## 存储和删除

全部记忆（含候选、来源、停用项和去重标记）随主资料存于当前网址的 localStorage，并包含在本机导出、导入、恢复与清除流程中。没有自动云同步或向量数据库。Key 独立保存在页面内存/选择的 sessionStorage，不进入记忆或提示词。

删除/不采用会移除该记忆，并保存内容和原句的去重哈希，减少相同候选反复出现。哈希只用于去重，不是加密保护。删除不清理原始小记、当天对话、上一版快照或旧备份；重新措辞的候选仍可能再次出现。需要清除原句时须同时管理这些来源。

## 验证边界

自动测试覆盖来源校验、候选与正式记忆隔离、有效日期、系统提示词、上下文失效、跨标签页更新、编辑、导入恢复与请求大小。上游使用模拟响应；没有用真实 Key 验收语义提取准确度、医疗有效性或付费账号权限。
