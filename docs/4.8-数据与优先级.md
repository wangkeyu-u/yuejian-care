# 4.8 数据流与检查边界

## 输入对应关系

| 输入 | 保存 | 日历与页面 | AI 上下文与失效 |
| --- | --- | --- | --- |
| 过敏食物 | partner.allergies | 当日排除项、饮食限制 | preferences.allergies + foodExclusions；旧菜单收起 |
| 普通忌口、医嘱文字 | partner.dietary | 当日饮食限制 | preferences.dietary；可识别过敏报告同时排除 |
| 今天可能某阶段 | 当日 phaseHint，tentative，默认到本日 | 双线标注、可能/待确认 | 服务端重算 phaseAssessment，选相应资料，所有领域共用 |
| 实际月经起止 | periods 稳定 ID | 出血与下次参考 | 优先于阶段猜测，感受日期不移动 |
| 当日感受与支持需求 | entries[公历日期] | 当天状态与优先行动 | 当天报告高于通常偏好；旧症状不自动视为仍持续 |
| 已采用记忆 | memory 条目、有效日期、复核日期 | 设置可更正/停用/删除 | 按问题选取；复核到期不自动当作痊愈 |

设置保存使用统一通知，同源多标签页通过 storage 事件刷新。未保存草稿继续保留；冲突不覆盖。刷新不自动调用模型。新回复必须匹配最新上下文签名；旧回复不能回填为有效建议。阶段记录本身可独立更正/移除，清理 AI 对话不等于删除实际感受与阶段记录。

## 约束与限度

过敏名称与常见衍生成分检查在浏览器与 Worker 共用。主餐和替换不允许出现排除食材；准备步骤、其他领域和聊天也检查冲突。命中时返回说明，不存半份结果、不自动重试。自定义项主要按字面匹配；未登记别名、陌生菜名及真实交叉接触无法靠文本校验证明安全。书籍和知识页的通用示例不是对本人的推荐；当日建议才结合个人限制。

原有明确过敏报告仍作为线索纳入，但未知、没有、是否、未提供不产生食材。更正过敏时，需要同时核对原饮食文字和已采用过敏记忆，避免旧报告继续生效。撤回偏好使用后不发送这些偏好；本地仍保留原资料以供管理。

独处时拒绝明显重复联系任务；文化关闭由程序固定为关闭状态并在界面隐藏。名称与话术检查不是对所有自然语言的完备证明；真实输出需结合原始场景评估。DeepSeek 简洁完整分析最多 2000 输出 token，不足时不保存；移除重复审核元数据，但保留知识正文、来源、段落映射及证据边界。

- Flo, Main screen：https://help.flo.health/hc/en-us/articles/4401756146452-What-can-I-find-on-the-main-screen 。用于研究当日记录与个性化建议的层次。

具体优先级、单日待确认状态、菜式与界面取舍是本站产品/工程设计，不伪称这些来源做过本应用有效性研究。
