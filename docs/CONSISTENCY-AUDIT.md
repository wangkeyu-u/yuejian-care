# 数据一致性、长期使用与建议质量核查

核查日期：2026-10-28；版本：4.5.1。使用合成数据、Node/JSDOM和独立本地浏览器页面，未向真实付费模型发送个人资料。

## 结论与修复

原有158项测试通过，但没有覆盖以下长期与交互边界。本轮补充可复现案例并修复：

| 问题 | 修复后的行为 | 回归证据 |
| --- | --- | --- |
| AI固定取最近24次经期，较早日期丢失起点 | 同时保留目标日前7次、目标后的下一次、当前最近7次，去重后最多15次；保留历史与当前预测各自所需窗口 | 90轮周期、450个日期点，AI与日历分期逐项对照 |
| 页面持续在前台跨午夜时日期不刷新 | 按上海日期每分钟检查，回到页面或窗口聚焦也检查；旧请求取消，旧分析失效 | 模拟23:59到00:00的前台定时器，旧响应不落盘 |
| 同步更新会覆盖未保存设置或阶段草稿 | 保留草稿；设置按组检查冲突，允许合并无关更新；同组冲突要求重新载入 | 两个真实浏览器标签，以及JSDOM并发更新案例 |
| 历史LH报告的日期范围或插入顺序可能造成前后端不一致 | 两端均只使用不晚于所选日的报告；投影按实际日期排序后取范围 | 同轮报告前、报告当天、报告后的分期对照 |
| 有效导出超过2MiB后无法重新导入 | 导入上限改为16MiB；导入仍先验证并可恢复导入前数据 | 超过2MiB、7天各50轮合成对话的导入/恢复 |
| 分析累计到366个日期会阻止新增 | 日期数量护栏扩为36525，仍受公历范围与浏览器存储空间限制；不自动删除旧对话 | 400天解码、追加、重载；配额失败保持原数据 |
| 长历史反复处理记忆屏障导致日历变慢 | 每次分期先构建来源日期索引，避免每条历史记录都重新规范化全部记忆 | 同规模性能探针，见下文 |
| 套话变体可通过行动校验 | 拦截明显空话、重复灌水、空泛餐食替换/准备；旧记录仍可读取 | `action-quality.test.cjs` 与新旧分析兼容案例 |
| 追问/记忆提取的提示里混入完整三餐要求 | 四种模式各用对应输出要求；追问处理当前问题，记忆/线索模式只整理候选 | 捕获模拟上游请求，核对instructions与JSON schema |
| 大量历史日期一次性生成全部列表 | 每次展示30个日期，可继续展开；显示本机用量，提供按日期清理AI对话及立即撤销 | 400天列表分页、清理/撤销与原始日期记录不变 |

清理单日AI对话是容量管理，保留经期、当天情况及已确认记忆；隐私删除仍走已有的来源清理事务。清理后的立即撤销也检查该日是否被另一页更新、记忆是否变化，避免恢复已清理来源。

验证结果：178项自动测试通过；构建与发布包检查通过。真实浏览器在独立本地来源验证了两标签即时同步、未保存草稿保留及同组冲突；没有使用线上个人档案。本轮浏览器的手机视口控制未生效，因此新数据管理区域只完成桌面渲染检查，没有把该检查计为手机验证。

## 数据对应与知识归位

| 数据 | 保存位置与对应规则 | 更新影响 |
| --- | --- | --- |
| 实际经期 | `periods`，稳定ID、公历起止、unknown/ongoing/ended | 更新日历、统计预测、分期、相关分析签名 |
| 当天情况/线索/标注 | `entries[YYYY-MM-DD]` | 不随经期起点移动；当天及相关近期上下文更新 |
| 长短期记忆 | 独立起止日、复核日、来源、表达者、版本与清理屏障 | 核对后使用；按问题选择；更正/停用/删除后旧上下文失效 |
| 每日AI对话 | `yuejian.days.v1`，日期与上下文签名 | 原日期查看；过期结果不继续用于追问；切日或设置变化丢弃旧请求 |
| API Key | 页面内存或明确选择的标签页会话 | 不进入个人资料、备份或知识库 |
| 知识 | 57篇：53篇专题、4篇分期；6本书用于阅读导航 | 日历/百科/服务端共用文章；百科聚焦可把对应资料带入当天上下文 |

逐条检查了57篇文章的169段正文和154处段落引用索引、来源支持范围、领域标签、关联文章及书目指向。4份分期照护统一按“认识、变化、行动、饮食活动、求助、边界”组织。所有文章均可从百科聚焦进入当天上下文；关闭文化内容后仍排除文化资料。

这项检查证明数据结构与引用连接完整，**不等于本轮逐句重新审核了全部医学知识，也不证明模型每一句话都由引用支持**。医学事实、照护原则、编辑行动示例及文化理论仍保留各自标记。分期来源与支持范围见[分期资料审计](PHASE-KNOWLEDGE.md)。

## 长期规模探针

相同运行环境、相同合成数据，每月判断42天；每组含100个记忆清理屏障：

| 数据规模 | 优化前 | 本轮脚本中位数 |
| --- | ---: | ---: |
| 5年，1825条每日情况 | 约1.66秒 | 约34毫秒 |
| 10年，3650条每日情况 | 约3.33秒 | 约61毫秒 |

测量范围仅为Node中的分期计算，不包括浏览器绘制、导入大文件或手机性能。处理仍随记录数增长，不能把这组结果解释为任意数据量都流畅。

## 怎样判断建议有实际价值

提示词现在要求：摘要先给一件值得现在做的事及对应依据，其余为可选备选；四领域避免重复同一任务；行动包含时机、任务、做法、调整条件。已确认且未到复核日的偏好可作为可拒绝的安排依据，未知信息先核对。没有领域依据时说明未知，不为填栏目虚构症状或疗效。

下列是后续真实模型抽样时的验收标准，**不是本轮已验证的模型回答**：

| 合成情境 | 有用回答应做到 | 不应出现 |
| --- | --- | --- |
| 当天没有填写感受 | 先核对一个具体需求，给可拒绝的一步 | 根据阶段断言她烦躁、缺铁、需要某食物 |
| 记录严重疼痛或异常出血 | 保留已有规则给出的医疗优先行动，再讨论陪同或整理资料 | 食疗、热敷或文化安排取代求助 |
| 明确说想独处 | 一次可拒绝的具体询问，提供实际减负 | 要求反复回复、见面或解释情绪 |
| 已记录过敏/饮食限制 | 使用相关已确认限制；资料冲突先确认；替换写具体食材组合 | 把通用菜单说成已适合她，自动补充营养制剂 |
| 只问黄体期或某顿饭 | 区分估算和本人情况，只处理当前问题 | 从行为确认阶段，重做无关四领域或三餐 |

自动校验能拒绝明显不完整、空泛或错误领域引用的结果；不能全面判断自然语言事实、个体适用性或行动执行后的效果。[OpenAI官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes)也明确，结构化输出仍可能包含内容错误。

## 剩余边界

- 实际可保存量由浏览器配额决定；界面显示估算用量，失败不覆盖原文。16MiB是文件读取护栏，不保证浏览器一定能保存同等大小的数据及自动备份。
- 当前最多100条记忆、24条同时适用，每个日期最多50轮对话；没有无限版本历史。容量管理不自动遗忘已确认的健康报告。
- 同浏览器标签页使用storage事件和冲突检查；localStorage不提供跨标签、多键写入的数据库级事务。已覆盖常见先后更新、冲突与回滚，未做多进程同时抢写压力认证。
- 数据不自动跨设备同步；清除浏览器存储仍需依靠外部备份恢复。
- 尚未使用真实Key进行模型质量抽样、长期真人使用或临床预测准确率评估。当前阶段估算与参考窗口均不代表个人实测概率。
